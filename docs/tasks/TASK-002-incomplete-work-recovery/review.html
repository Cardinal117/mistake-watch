TASK-002.8J Security checkpoint Spec-first Generated 2026-07-07

Uploaded media access hardening and room playback sessions

Current recommendation: implement the uploaded-media security slice before more catalogue UI polish or roadmap progression. The goal is a private uploaded catalogue with shared room playback, without leaking permanent private R2 URLs.

Executive Summary

Immediate risk

Permanent URL leakage

Private uploaded assets can still move through source-match, queue, live room, dashboard, or player state as permanent URLs. Hiding the uploaded tab is not enough.

Model

Private catalogue, shared playback

Only authorized Google users browse/start uploaded media. Once started, valid room participants can watch the active session without catalogue access.

Next action

Implement in batches

Start with source-match no-leak filtering, then add permission helpers, room media sessions, playback URL resolution, and final QA gates.

Implementation Batches

Patch current source-match leaks

Return only authorized uploaded matches. Do not expose private asset URLs or object keys. Add no-leak tests.

Add authorization helpers and allowlist model

Google identity is not catalogue authorization. Add server-side helpers and app-owned records with tests.

Add room media sessions

Create active uploaded-media playback sessions only after start authorization passes.

Add playback URL resolver

Validate room participant plus active session, then issue a temporary R2 URL. Do not persist signed URLs.

Migrate queue, live state, and player flow

Private uploaded media should use opaque session references, not permanent public URLs.

Run production security QA

Test owner, whitelisted user, non-whitelisted signed-in user, and guest. Inspect serialized payloads for leakage.
