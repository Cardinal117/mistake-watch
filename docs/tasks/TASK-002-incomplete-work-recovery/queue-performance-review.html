Implementation Batches

Each batch is independently testable and has a safe commit point.

A

Benchmark and linear state

Capture the baseline, add fixtures/instrumentation, and remove repeated per-row queue scans.

B

Bounded metadata

First 10 immediately, priority scheduling, maximum concurrency of 3, cancellation, and stale-result guards.

C

Drawer isolation and virtualization

Zero full rows while closed and at most 30 mounted rows for a 250-item open queue.

D

Failure resilience and events

Permanent-failure-only auto-skip, compact room events, known-bad labels, and no silent queue drain.

E

Production release gate

Full regression suite, same-profile benchmark, deploy, manual owner/guest QA, and post-deploy field comparison.

Implementation Decision

Proceed

Start with Batch A

Do not optimize before the controlled pre-change benchmark is captured. Batch A also removes quadratic derived-state work with no intended visual change.

Do not combine

Keep batches reviewable

Metadata scheduling, virtualization, and failure events have different regression risks and should not land as one large rewrite.
