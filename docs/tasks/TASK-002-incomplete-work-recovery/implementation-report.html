TASK-002.5C / Implementation Report

Live Room Authority Hardening

This slice closes the browser-authoritative live-session seed path, aligns queue-item play-now with playback permission, adds reducer-level duplicate queue protection, and guards provider-backed room routes behind verified room membership.

Implemented

Authority Boundary

SpacetimeDB session seeding now requires a server-issued seed token for the durable host member.

Verified

Automated Checks

Typecheck, lint, Spacetime tests, queue tests, sync tests, YouTube tests, Next build, Spacetime build, and code generation passed.

Manual QA Pending

Live Room Review

Two-client room QA is still needed for fresh-session seeding, permission revocation, and duplicate playlist imports.

What Changed

Trusted Session Seeding

  • Added a server-issued private SpacetimeDB seed grant derived from verified durable host membership.
  • Exposed the one-time token only on the host's room snapshot.
  • Required `seed_token` plus a matching private `room_seed_grant` in the SpacetimeDB `seed_room_session` reducer.
  • Stopped guests from attempting to seed a live room session from the browser.

Permissions And Queue Safety

  • `play_queue_item` now accepts playback-authorized actors instead of host-only actors.
  • `add_queue_item` now ignores duplicate active source URLs at reducer level.
  • Playlist/recommendation routes now require active room membership and rate limit requests.
  • Provider request clients pass `roomId` and keep caches room-scoped.
