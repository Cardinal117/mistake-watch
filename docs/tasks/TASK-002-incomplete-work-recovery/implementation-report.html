Implementation Summary

  • Added queue-aware next-item prediction that respects current item, queue order, queue mode, and loop behavior.
  • Added invalidation keys so reorder, shuffle, loop mode, source changes, and active item changes drop stale preparation targets.
  • Added YouTube preparation for thumbnails, provider metadata, and IFrame API readiness without hidden duplicate players or video preloading.
  • Added direct and HLS metadata warming where browser and network conditions allow.
  • Added data-saver and slow-network skip handling so preparation does not waste bandwidth on constrained clients.
  • Added visible next-item preparation status in watch and listen control surfaces.
  • Added performance marks, measures, and a mw:next-item-preparation event for future transition timing QA.
  • Refined listen-mode metadata display so useful cards do not show repeated pending states.
  • Refined the listen source card, next-preparation status strip, members permissions, carousel affordance, and red/dark theme strength.
  • Added a compact technical room header for room state, invite controls, save room, and mode switching.
  • Removed duplicated room-wide controls from the right sidebar so it focuses on members and permissions.
  • Replaced homepage-style listen-room language with active session language and tightened shared control radii.
  • Grouped YouTube source, views, and likes into compact stat chips below the artist line.
  • Moved Preparing Next into an attached bottom strip on the now-playing card with next-item artwork.
  • Added a collapsible right members sidebar with an attached live member rail, persisted collapsed state, and animated desktop grid/drawer offsets.
  • Removed the duplicate right-panel Coming Up card because the now-playing card already owns the Preparing Next preview.
  • Refined the members panel into compact table-like active/idle sections, sorted hosts and online members first, and hid host self-management controls.
  • Made listen room pick cards and recently added rows clickable, permission-aware playback actions.
  • Softened the center listen canvas background so recommendation tabs no longer sit in a mismatched color band.
  • Split the listen queue drawer into Queue and History views so played songs no longer mix into the upcoming queue.
  • Added YouTube player runtime guards before player API calls such as getPlayerState.
  • Kept the YouTube iframe player stable across queue transitions by loading the next video through the existing IFrame API instance instead of remounting.
  • Added a near-end fallback that advances the canonical queue once when YouTube misses ENDED in a backgrounded or throttled tab.
  • Changed automatic next-item advancement to require playback authority rather than full queue-management authority.
  • Added visibility-return resync so returning to a tab aligns the local YouTube player to SpacetimeDB room state without blind autoplay.
  • Changed the blocked-autoplay affordance to a compact Resume playback recovery control.
  • Compressed the listen room header into a technical session strip with inline room-name editing and clearer session stats.
  • Changed listen header stats to show upcoming count, played count, and remaining duration when queued item durations are available.
  • Rebalanced listen header actions so Add Media is primary while Save, Copy Link, Share, and room code read as secondary controls.
  • Integrated the Watch/Listen mode switch into the compact header and tightened Room Picks tabs plus carousel affordance without redesigning the cards.

A local browser check was attempted after verification: npm run dev:next printed Ready on port 5371, but the in-app browser client blocked navigation to both 127.0.0.1:5371 and localhost:5371 with ERR_BLOCKED_BY_CLIENT. Manual QA should confirm that preparation status appears during real queue transitions, stale preparation targets are invalidated after reorder or mode changes, and next-item readiness does not interrupt current playback or cause time jumps. Additional manual QA should tab away shortly before a YouTube item ends, wait for the next item to become canonical, then return and confirm playback resumes or shows the compact recovery control instead of silently stalling. The listen header should also be checked visually in production for compact height, inline room-name editing, action hierarchy, active Listen state, and Room Picks carousel alignment.
