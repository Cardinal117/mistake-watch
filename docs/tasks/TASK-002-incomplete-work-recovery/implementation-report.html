TASK-002.8 Implementation Report

R2 media library and owner-authorized upload pipeline

TASK-002.8 is implemented as the R2-first private-room media path. Owner accounts can create signed upload intents, upload browser-playable MP4 files directly to R2, complete metadata into Supabase, and surface ready assets inside the Watch Media Hub. Guests and non-owners can browse ready media and use existing queue/playback actions where room permissions allow.

TASK-002.8D Large Upload Refinement

Multipart Upload Path

  • Uploads below 500 MB keep the existing single signed PUT flow.
  • Uploads at or above 500 MB use R2 multipart upload with 64 MB parts and 3-way browser concurrency.
  • Each part URL is requested shortly before use so long uploads are less likely to hit expired signatures.
  • Multipart upload sessions remain valid for 24 hours while individual part URLs stay short-lived.
  • Failed parts retry up to 3 times without restarting already completed parts.

Progress and Safety

  • Single and multipart uploads now share one clear byte-based progress bar.
  • Supabase tracks upload mode, part size/count, completed ETags, uploaded bytes, and abort/finalizing states.
  • The media asset row is created only after multipart completion and R2 object-size verification succeed.
  • R2 credentials remain server-only; browser code receives only scoped signed URLs.

TASK-002.8C Refinement

Uploaded Library UX

  • Uploaded media now has explicit folder creation instead of implicit folder-name typing.
  • The Uploaded tab is folder-first, with quick views for all media, unsorted items, and live items.
  • Grid and list views are available; grid keeps cards clean, while list exposes direct Play, Add Next, and Queue buttons.
  • Search uses normalized partial matching instead of exact/case-sensitive matching.

Management and Permissions

  • Card settings now contain Play Now, Add Next, Add to Queue, Move to Folder, and visibility controls.
  • Folders store persistent sort key/direction, and folder-level queue actions use that ordering.
  • Uploaded assets can be marked public or owner_only; non-owners do not receive hidden assets.
  • Watch history/resume, transcoding, MKV conversion, and friend-only visibility remain deferred.

TASK-002.8E Credit Efficiency

Processing Decision Gate

  • Uploads now inspect media before spending CloudConvert credits.
  • Confident MP4/H.264/AAC files become direct_ready and play from R2 without conversion.
  • Unsupported or uncertain files still convert automatically when they are small enough.
  • Large, long, or unknown-duration large uploads wait for explicit owner approval.

Owner Visibility

  • Media assets store inspection result, processing strategy, estimated credits, and approval state.
  • Uploaded cards show Direct, Converting, and Needs approval states with owner-only approval action.
  • The Account CloudConvert section now reports direct-ready, converted, approval-required, and estimated credits avoided counts.
  • Direct-ready assets keep best-effort browser poster capture without forcing full conversion.

TASK-002.8F Multipart Recovery

Recoverable Uploads

  • Failed multipart sessions now stay recoverable until their resumable_until window expires.
  • The Watch Media Hub shows owner-only recoverable upload rows with filename, uploaded bytes, error state, Resume, Cancel, and progress.
  • Resume requires reselecting the same local file, validates name/size/type, and uploads only missing R2 parts.
  • Completed part ETags remain stored in media_upload_sessions.completed_parts and are reused during completion.

Cleanup Path

  • Cancel reuses the R2 multipart abort path and marks the session aborted.
  • Expired cleanup route aborts stale incomplete multipart uploads and marks sessions expired.
  • vercel.json schedules hourly cleanup through Vercel Cron.
  • Production cleanup requires CRON_SECRET authorization; R2 lifecycle cleanup remains the backup safety layer.
