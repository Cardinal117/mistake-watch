Spec Review · TASK-006

Media Session controls make Mistake Watch feel native in browser media surfaces.

This packet scopes a small quality-of-life enhancement: publish now-playing metadata and bind permission-aware media-key controls through the browser Media Session API. It is progressive enhancement only, with no database, storage, or playback architecture rewrite.

Status Ready for implementation approval
Task Type Guided Plan First
Start Phrase JARVIS, suit up
Goal

Now Playing Metadata

Show active room title, source, artwork, playback state, and position in supported browser media controls.

Controls

Permission-Aware Keys

Route play, pause, seek, next, and previous through existing live-room actions only when the participant can control playback.

Boundary

No URL Leaks

Uploaded-media metadata must not expose signed R2 URLs, permanent media URLs, object keys, or private storage identifiers.

Implementation Flow
1. Helper

Build browser-safe Media Session utilities and focused tests.

2. Hook

Map existing transport state to metadata and action handlers.

3. Safety

Protect uploaded media from artwork or metadata URL leakage.

4. QA

Verify Chromium, Opera GX sidebar where available, permissions, tests, lint, typecheck, and build.

Decisions
  • Use the Media Session API as a progressive enhancement.
  • Integrate from `TransportControls`, not from random player UI.
  • Show metadata to participants where supported, but bind mutating controls only for controllers.
  • Use app icon fallback artwork for private uploaded media unless safe poster delivery is proven.
Risks
  • YouTube iframe metadata may override the parent page in some browsers.
  • Opera GX sidebar behavior needs real browser QA.
  • Position-state updates should avoid unnecessary API churn.
  • Media-key handlers must not bypass room playback permissions.
