# Approved audit corrections — F1–F5

Status: approved and implemented 2026-09-09; local QA passed. High effort. Local only.

Scope is the five findings in [audit](audit-2026-09-09.md); no 028.5/028.6 implementation, new ranker, Git publication or hosted changes.

## Contract and approach

- F1: use user-scoped Shared room visibility when filtering the admin-backed account list. Ineligible/removed accounts see no Shared metadata; existing Legacy listing semantics remain.
- F2: each consent scope has its own opaque epoch and start time carried across changes to the other switch. Eligibility records retain both scope epochs; reads compare each independently with the current consent. Withdrawal/regrant starts a new epoch only for the changed scope. Existing revoked history stays revoked during migration; do not reconstruct lost consent. No private epochs leave the server.
- F3: normal room navigation preserves membership. Account Leave permanently withdraws the caller's Shared membership, revokes consent, removes public membership/permissions and retires the live member ID through the existing trusted revocation flow. Derive identity from Auth; forbid owner self-withdrawal; serialize with owner decisions/consent. Retry remains possible after durable withdrawal, and owner retry remains available if the leaver reloads. Reapproval waits for live acknowledgement and gives a fresh ID. Legacy account Leave stays unchanged.
- F4: accept the trusted queue_play_next/add_as_next producer pairing alongside priority_play_next; neutral events and replay deduplication remain unchanged.
- F5: automatic Listen suggestions exclude uploaded catalogue items, including queue/history fallback and provider candidate inputs. Factual history/manual queue and catalogue remain accessible. Enforce server candidate exclusion using trusted durable mode, including cache mode isolation; do not trust a client-supplied mode.

## Database and authority boundaries

Add an incremental local migration, preserving previous migrations and existing consent evidence. Private consent/eligibility columns keep their existing RLS/grants. Live revocation continues through the existing server-only reducer; no Spacetime schema change is planned. No hosted migration is authorized.
