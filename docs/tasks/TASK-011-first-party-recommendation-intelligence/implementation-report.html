What changed

  • Canonical transition events now originate inside authorized reducers.
  • Playback occurrence IDs prevent stale advances and source failures from mutating newer replays.
  • Completion requires an ended state or at least 90% progress.
  • Guest Likes are private, revision-checked, idempotent, and neutral when removed.
  • Member IDs cannot be rebound to another SpacetimeDB identity.
  • Smart Shuffle shares one action ID across its move reducers, so one shuffle creates one operational event without suppressing a later shuffle.
  • Pending outbox rows are never pruned; overflow is counted and logged.
  • One atomic service-role RPC inserts immutable events, updates only newly accepted aggregate rows, and rejects conflicting idempotency collisions.
  • Non-personal event-key tombstones remain for 180 days so deleting account-linked recommendation data cannot make an unacknowledged retry count as new guest activity.
  • Account attribution requires matching room, member, and user IDs in both application and database checks. Guest activity remains room-session scoped.
  • Signed-in Likes persist until neutralized or the account is deleted; stale toggles cannot overwrite newer state and neutral rows expire after 30 days.
  • A CRON-secret-protected drain route acknowledges SpacetimeDB only after Supabase returns internally consistent persistence counts.
  • A pure ranker now applies hard exclusions, stable integer component scores, factual reasons, canonical tie-breaking, and bounded artist/channel/source diversity without network or UI dependencies.
  • Uploaded candidates fail closed without explicit catalogue authorization. Like remains the strongest individual positive signal; neutral and missing Like state never become negative.
  • Private recommendation and preference routes now enforce bounded, URL-free contracts, active participant state, catalogue scope, streamed byte limits, and capacity-bounded cache behavior.
  • Existing Listen Room Picks adopt first-party ordering only when it is authoritative. Provider failures retain the original order and authoritative empty results do not restore excluded candidates.
  • A shared accessible Heart supports Like and Remove Like on now-playing and recommendation cards with optimistic rollback, stale-room protection, and announced errors.
